# Pancreatic Cancer in LMICs — Value of Lost Welfare: Reproducibility Package

Analysis code for *Economic welfare burden of pancreatic cancer in low- and middle-income countries:
trends from 1990 to 2023 and projections to 2050* (manuscript ISCIENCE-D-26-05974).

The study quantifies the welfare-based economic burden (value of lost welfare, VLW) of pancreatic
cancer across 122 low- and middle-income countries from 1990 to 2023, and projects it to 2050.

## Repository contents

| Path | Contents |
|---|---|
| `scripts/` | The complete analysis: entry point, canonical implementation, submission-table builder, and the additional reviewer-requested analyses |
| `fig/` | The 19 manuscript figures under their manuscript names, plus a standalone script for each one (see `fig/README.md`) |
| `table/` | Supplementary Tables 1-17 **numbered as in the manuscript**, plus a standalone script for each one (see `table/README.md`) |
| `LICENSE` | Licence |

**Input data are not redistributed here.** `data_raw/` is excluded; see *Obtaining the input data*
below. The generated `outputs/` **is** committed so that the figures, tables and diagnostics used in
the submission can be inspected without re-running the pipeline. Every output is regenerated by
running the scripts.

## Scripts

| Script | Purpose |
|---|---|
| `run_LMIC_Pancreatic_VLW_R3.R` | **Entry point.** Resolves the working directory and sources the canonical implementation. |
| `run_LMIC_Pancreatic_VLW_v2.R` | The complete implementation, kept under its historical filename for continuity. Not called directly. |
| `run_R5_reviewer_analyses.R` | Every analysis Reviewer #3 asked for at the R5 round: rolling-origin validation over all four candidate models, the prespecified selection rule applied to the primary DALY series, full-sample residual diagnostics, ARIMA coefficients, sex-specific reconciliation, exclusion fractions, the fixed-composition sensitivity, **rolling-origin validation of the complete aggregate interval construction**, full disclosure of the joint simulation, the input manifest and the MASE definition. |
| `make_submission_xlsx.R` | Builds the submission xlsx tables from the generated CSVs. |
| `rebuild_fig_common.R` | Regenerates `fig/code/_common.R` from the canonical script, so the per-figure preamble cannot drift from it. |
| `_env.R` | Pins ggplot2/scales to the versions the figures were produced under. Sourced by the entry points; see below. |

```bash
Rscript scripts/run_LMIC_Pancreatic_VLW_R3.R    # full analysis: figures, tables, diagnostics
Rscript scripts/run_R5_reviewer_analyses.R      # all reviewer analyses              -> outputs/R5/
Rscript "fig/code/make_all_figures.R"           # all 19 figures, or one script per figure
Rscript "table/code/make_all_supplementary_tables.R" # Supplementary Tables 1-17
Rscript scripts/make_submission_xlsx.R          # all 23 submission tables as xlsx
```

Run them in this order: `make_submission_xlsx.R` reads CSVs written by the first two scripts.
The full pipeline takes about 15 s, the R5 reviewer analyses about 40 s, the figure scripts
about 50 s. `RUN_LOG_*.txt` records a complete clean run.

## Obtaining the input data

Place the following under `data_raw/` before running:

- `data_raw/gbd_daly_yearly/measure2_DALYs_year{1990..2023}.csv` — 34 annual pancreatic-cancer DALY
  extracts (cause 456, measure 2) from the **GBD 2023** results tool at
  <https://vizhub.healthdata.org/gbd-results/>, for all 204 locations, both sexes and all age groups,
  in both number and rate metrics.
- `data_raw/external_metadata/HALE.csv` — GBD 2023 healthy life expectancy.
- `data_raw/external_metadata/gdp.csv` — World Bank World Development Indicators,
  `NY.GDP.PCAP.PP.CD` and `NY.GDP.MKTP.PP.CD`.
- `data_raw/external_metadata/204_with_LMIC.csv` — GBD location list with the World Bank income
  classification flag.
- `data_raw/external_metadata/df_world2.geojson` — world map geometry keyed by GBD `location_id`.

GBD and World Bank data are redistributed under their own terms, which is why they are not committed
here.

## Statistical policies implemented

- Historical marginal lower/upper bounds are never summed. Aggregate historical 95% uncertainty
  intervals are not reported, because matched GBD draws are unavailable.
- DALYs are the primary projection estimand; projected DALYs are then monetised using fixed 2023
  income-group effective VSLYs.
- **Projection ranges are model-dependent scenario ranges, not calibrated prediction intervals.**
  Rolling-origin validation puts the empirical coverage of the nominal 95% construction at 55.1%
  for single series and 43.5% for the aggregate, falling to 47.2% and 11.1% respectively at a
  six-year horizon. The nominal level is retained only as a construction parameter, under the
  column name `scenario_nominal_level`, and no probability statement is attached to any range.
- All-LMIC ranges come from 50,000 draws per horizon coupled by the fixed cross-sectional residual
  correlation; subgroup interval endpoints are never summed. Horizons are simulated independently,
  so the draws are pointwise per year and are **not** coherent temporal forecast paths.
- The rate panel is the unweighted mean of country-specific age-standardised DALY rates.
- One discounted-annuity VSLY definition is used throughout; both-sex values are male plus female.
- IE = 0.5, 1.0 and 1.5 are valuation scenarios, not statistical uncertainty bounds.

Reference constants: US DOT 2023 VSL = US$13.2 million; US 2023 PPP GDP per capita = 82,304.62
international $; base discount rate 3%.

### Forecast model and the selection rule

Four models are evaluated, and **all four are candidates**: damped-trend ETS, automatically
selected non-seasonal ARIMA, the naive random walk, and the random walk with drift. None is
relegated to a benchmark role and none is excluded on the basis of observed performance.

The prespecified rule is: *among candidates whose residuals show no detected autocorrelation at
the 5% level (Ljung-Box), select the one with the lowest pooled rolling-origin MAPE over horizons
1-6.* It is applied **per primary DALY series**, because the aggregate projection is built from
the three income-group DALY series.

`run_R5_reviewer_analyses.R` runs 14 expanding-window origins x horizons 1-6 x 4 models x 8
series and writes the selection table to `outputs/R5/R5_model_selection_primary_DALY.csv`.
Applying the rule with every method eligible selects ARIMA on all three primary DALY series:
drift attains a lower MAPE than ARIMA on the upper-middle-income DALY series (3.88% vs 4.11%) but
shows residual autocorrelation there (Ljung-Box p = 0.016), as it does on all eight series, and is
therefore ineligible under the residual criterion rather than under any post-hoc argument.

`run_R5_reviewer_analyses.R` then validates the aggregate interval construction itself. The
published all-LMIC range is not a single model's forecast interval: it is the 2.5th and 97.5th
percentile of a 50,000-draw joint simulation across the three income groups. That construction is
rebuilt from training data at every origin -- models refitted, correlation re-estimated, valuation
input taken from the final training year -- and compared with the realised aggregate.

## Environment

R 4.2.2 on aarch64-apple-darwin20 (macOS 14.5), with tidyverse 2.0.0, ggplot2 3.5.1, sf 1.0-16,
forecast 8.21.1, patchwork 1.2.0 and scales 1.3.0.

**ggplot2 must be 3.5.x.** ggplot2 4.0 rebuilt plot objects on S7, which is incompatible with the
`&` operator of patchwork < 1.3. Every multi-panel figure here uses
`plot + plot_annotation(...) & theme(...)`, so under ggplot2 4.0 all 19 figure scripts fail with
`operations are possible only for numeric, logical or complex types`.

`scripts/_env.R` prepends `code/.Rlibs` to the library path when that directory exists, so the
pinned versions are used without altering the main R library. To create it:

```bash
Rscript -e 'dir.create("code/.Rlibs"); \
  install.packages(c("https://cran.r-project.org/src/contrib/Archive/scales/scales_1.3.0.tar.gz", \
                     "https://cran.r-project.org/src/contrib/Archive/ggplot2/ggplot2_3.5.1.tar.gz"), \
                   repos = NULL, type = "source", lib = "code/.Rlibs")'
```

`.Rlibs` is a local build artefact and is not committed. Each entry point prints the versions it
actually loaded, so a mismatch appears in the run log instead of failing silently.

### Submitted workbooks versus repository workbooks

The xlsx files in the submitted attachment set are **hand-formatted** from the same CSVs that
`make_submission_xlsx.R` reads. The submitted workbooks therefore contain exactly the numbers that
appear in the manuscript and response letter, but they may differ cosmetically from the machine-
generated workbooks in `table/` and `outputs/submission_tables_xlsx/`:

- Some multi-section tables are stacked onto one worksheet behind banner rows in the submitted
  version, whereas the repository version gives each section its own worksheet.
- A few tables omit explanatory columns (for example, the `Non-positive simulation draws` column in
  S13, which is all zeros) or combine low/high bounds into a single range string for readability.
- S14 in the submitted set contains only the by-income-group summary, while the repository also
  includes the by-country sheet.

Where the same numeric value appears in both versions, it is identical. The two remaining cells
(3,534/3,536) differ only in display: S5 reports the relative reconciliation difference as a
fraction in the repository (`0.0233`) and as a percentage in the submitted workbook (`2.33%`), and
S7 reports the "difference from self" as the literal zero in the submitted workbook. See
`table/README.md` for details.

## Data provenance

Access dates, query parameters, indicator and cause codes, classification vintage, fixed source
URLs, file names, file sizes, row and column counts and MD5 checksums are recorded in two
manifests written by `scripts/run_R5_reviewer_analyses.R`:

| File | Contents |
|---|---|
| `outputs/R5/R5_query_manifest.csv` | one row per source: access date, portal and fixed URL, exact query parameters, indicator and cause codes, classification vintage, downloaded files, licence |
| `outputs/R5/R5_data_provenance_manifest.csv` | one row per input file: size, local timestamp, MD5, rows, columns |

Everything that can be read back out of the downloaded files is derived from them rather than
typed, so the manifest cannot drift from the data. Two fields cannot be recovered from any file
and are author knowledge: the date the files were downloaded, and the classification vintage in
force at that date. Both live in `data_raw/EXTRACTION_DATES.csv`, and the script prints a loud
OUTSTANDING block and refuses to pass silently while either is still a placeholder. A file
timestamp is not a query date and is never used as one.

The data used in this analysis were obtained on **5 April 2026**, the date reported in the
Methods and in references 19-21 of the manuscript. Every source is served from a fixed URL rather
than as a versioned release, so that date records when the authors downloaded the files; the same
query against the same URL returns the same data.
